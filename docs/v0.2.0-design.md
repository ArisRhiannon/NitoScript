# NitoScript v0.2.0 — Design & Implementation Plan

Status: **DRAFT for approval** · Supersedes the esoteric v0.1.x surface · No code until sign-off.

---

## 1. Thesis (the frontier selling point)

**NitoScript is the beginner language where every program is a *Chain* of *Blocks* — a
deterministic, replayable state machine. The same code that teaches you to count is, at its
core, already a verifiable ledger.**

Programming = snapping **Blocks** (named actions, clear inputs → one output) into **Chains**
(ordered compositions that carry state). Because every Chain is deterministic and its state
is hash-linked, a Chain *validates itself by replay* — which is exactly what a lightweight,
PoW-free blockchain needs. NitoChain (later) just distributes Chains; the verifiable core
ships in 0.2.0.

Design adjectives, enforced: **Comfy · Simple · Elegant · Logical · Honest** (errors are real,
never silently "healed").

---

## 1bis. Nito — the central axis (el eje central de todo)

Everything in NitoScript turns around one value: **`Nito`**. Not as esoteric "supreme
dominance" (that arithmetic axiom is gone), but as the single point the whole system pivots on:

- **Origin of all state.** Every unbound variable, every missing field, and every Chain's
  initial state *is* `Nito`. A Chain's genesis root is `hash(Nito)` — so **all chains share one
  canonical origin** and any chain's lineage is verifiable all the way back to Nito.
- **Absence that propagates (Maybe at the core).** Any operation touching `Nito` yields `Nito`
  (`Nito + 5 → Nito`, `Nito.field → Nito`). Nothing crashes; absence flows through and you
  collapse it explicitly with `or`: `x or default`. Principled null-propagation — looks like the
  old "absorption" but means *missing-data*, not heresy.
- **The unit of value.** NitoChain's native token *is* Nito; balances are denominated in Nito.
  (Deferred, but the axis is reserved now — `state` balances are Nito amounts.)
- **Identity of composition.** A flow chain begins from Nito; blocks carry it toward a value.

So `Nito` is simultaneously the empty, the origin, the unit of value, and the safe default — the
axis every Block and Chain turns around. De-esotericized, yet more central than in v0.1.x.

## 2. NitoSupremeExecutor — kept, de-mystified, given a real job

Old role: bytecode VM dressed up as "Nito camina/haz". New role, frontier and concrete:

> **NitoSupremeExecutor = the Verifiable State-Transition Executor.**

Responsibilities:
1. Execute Blocks/Chains on the bytecode VM **deterministically** (no wall-clock, no unseeded
   RNG, fixed iteration order; nondeterministic FFI is forbidden *inside* a chain).
2. After each Chain transition, compute a **state root**:
   ```
   root_0    = hash("GENESIS" || canonical(initial_state))
   root_n    = hash(root_{n-1} || block_name || canonical(args) || canonical(new_state))
   ```
3. Expose **verify-by-replay**: re-execute a Chain's history from genesis, recompute each root,
   and confirm it matches the recorded chain. Tampering with any past transition changes every
   subsequent root → detected. Cost = one deterministic run + one hash per step. No mining.

This is *why the lightweight chain is secure yet cheap*, and it's a genuine, non-decorative
reason for the executor to exist. A single server validates a transaction by replaying it.

## 3. Core model: Block-and-Chain

- **Block** — a deterministic unit: named, typed-by-use inputs, one output via `give`.
  Pure: reads only its inputs (and, inside a chain, the chain's declared `state`).
- **Flow Chain** — value piped through blocks with `|>` ("do this, then this"). For beginners.
- **State Chain** — a `state` plus `block` transitions over it. *This is structurally a
  contract*: e.g. a wallet with `balance` and `deposit`/`withdraw` is already a token ledger.
  NitoChain "tokens Nito" = a State Chain whose state is balances and whose blocks are transfers.

Every State Chain is backed by NitoSupremeExecutor, so it gets `root`, `history`, `verify()`,
`replay()` for free. That is the "chain creation is core, not superficial" requirement.

## 4. Surface syntax (English keywords, indentation blocks)

Minimal keyword set (one obvious way to do things):
`block · chain · state · let · if · else · while · give · show · fail · use · new · true · false · Nito`
Operators: arithmetic `+ - * / %`, comparison `== != < > <= >=`, logic `and or not`,
flow `|>`, coalesce `or` (default for missing/`Nito`).

```nito
# Block: deterministic action, input -> output
block double(x):
    give x * 2

# Flow chain: snap blocks together
let r = 5 |> double |> double        # 20
show r

# State chain == a self-verifying ledger (and, structurally, a token contract)
chain Wallet:
    state:
        balance = 0
    block deposit(amount):
        balance = balance + amount
    block withdraw(amount):
        if balance >= amount:
            balance = balance - amount
        else:
            fail "Insufficient funds"

let w = new Wallet()
w.deposit(100)
w.withdraw(30)
show w.balance        # 70
show w.root           # state root (hash) — the verifiable fingerprint
show w.verify()       # true  (replays from genesis, re-checks every root)
```

Null-safety (was QuantumNito, now just the default + `Nito`): reading a missing field yields
`Nito` instead of crashing; `value or fallback` collapses it.
```nito
let name = event.author.username or "Guest"   # never crashes on missing data
```

## 5. What is REMOVED (de-esoterize; "actually works")

| Removed | Why |
| --- | --- |
| `NitoSupreme` axiom, heresy, `SupremeViolationError` | Esoteric; `Nito` reframed as the empty/nothing value. |
| Levenshtein keyword "auto-healing" | Silently miscompiles; replaced by clear errors. |
| Grammar-repair placeholder injection | Produces silently-wrong results. |
| Regex fallback "Inteligencia Propia" | Hides real bugs; not a real interpreter. |
| Spanish `nito_*` keyword grammar | Replaced by the English minimal set above. |
| `web/` (NitoBlocks IDE), `server.py` | No IDE for now. **Tag `v0.1.3` as backup before deleting.** |

## 7. NitoChain readiness (what 0.2.0 ships vs defers)

**Ships now (real, tested):** determinism enforcement, hash-linked state roots, `verify()` /
`replay()` / `history` / `root`. A single server can validate any Chain by replay.

**Designed-for, deferred (NitoChain proper):** signatures on transitions (the model leaves a
`signer` slot), networking/replication, multi-validator, lattice/CRDT **merge** of independent
chains, token economics. None implemented in 0.2.0 — but nothing about them requires changing
the Chain semantics we ship. That is the "switch-flip later" guarantee.

"Lightweight & cheap": security comes from hashing + deterministic replay, **not** from
proof-of-work. One validator, one hash per transition.

## 8. Phased plan (each phase: TDD red→green, verified before moving on)

- **F0 — Cut & clean.** Tag `v0.1.3`; delete `web/` + `server.py`; remove heresy/healing/fallback;
  keep VM core. *Verify:* repo runs, no dead imports.
- **F1 — New surface.** Rewrite lexer/parser to the English minimal grammar, indentation blocks,
  `Nito` as empty. *Verify:* parse+run `let/if/else/while/show/use`, clear errors on bad syntax.
- **F2 — Blocks.** `block name(p): … give e`. Reuse VM function machinery. *Verify:* `double`, nesting.
- **F3 — Flow chains.** `|>` desugars to chained calls. *Verify:* `5 |> double |> double == 20`.
- **F4 — State chains.** `chain/state/block-transition` → runtime state-machine object + method
  dispatch + ordered transition log. *Verify:* Wallet deposit/withdraw, `fail` on overdraw.
- **F5 — Verifiability (the selling point).** NitoSupremeExecutor computes hash-linked roots;
  `root/history/verify()/replay()`; determinism guard inside chains. *Verify:* replay reproduces
  root; tampering a past transition makes `verify()` return false; nondeterministic FFI in a
  chain is rejected. **This phase must be real and tested or the thesis is smoke.**
- **F6 — Beginner polish.** Friendly error messages, new REPL banner, 2–3 tutorial `.nito` files,
  full README rewrite, version → `0.2.0`. *Verify:* a newcomer can run the tutorials.

Honest scope note: F1 is a surface rewrite (new grammar); F4–F5 are substantial new runtime.
The fixed VM core is reused. This is a multi-session effort, not a quick patch.

## 9. Micro-decisions (decided with rationale — say the word to override)

- `give` over `return` (reads "a block gives an output"; comfier for beginners).
- `let` for binding; reassignment via `=` (no const/var split in 0.2.0 core).
- `show` over `print`; `fail` for errors; `use` for FFI; `new` to instantiate a chain.
- Indentation-only blocks (drop `{}` — one logical way, less noise).
- `Nito` = the empty/nothing value; "Nito tokens" is a NitoChain-layer concept, not the literal.
